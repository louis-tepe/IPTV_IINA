# Architecture Overview (v8.0.0)

## Project Structure

- `Info.json`: Plugin manifest (permissions, metadata).
- `global.js`: Global entry point (runs once on IINA start). Handles app lifecycle and global menus.
- `main.js`: Player entry point (runs per player window). Handles playback events.
- `package.json`: NPM configuration with Parcel bundler setup.
- `src/`: Core logic modules.
  - `api/`: Networking and external service integration (Xtream Codes API).
  - `core/`: Core utilities (State management, i18n, Logger).
  - `managers/`: Business logic (Cache, EPG, Storage).
  - `utils/`: Helper utilities (Logger, Base64, timeout wrappers).
- `ui/`: HTML/CSS assets for WebViews (`browser.html`, `connection.html`).
- `dist/`: Bundled output (generated by Parcel, not in version control).

## Module Organization

### Core Modules (`src/core/`)
- **state.js**: Global state, constants, configuration
- **i18n.js**: Internationalization (FR/EN) with translation dictionaries

### API Layer (`src/api/`)
- **xtream.js**: Xtream Codes API client using `iina.http`

### Managers (`src/managers/`)
- **cache.js**: Caching logic with virtual scrolling support
- **epg.js**: EPG data fetching (simplified, no batching)
- **storage.js**: Credentials, history, favorites, resume positions

### Utilities (`src/utils/`)
- **helpers.js**: Central Logger, Base64 encoding, timeout wrappers

## Data Flow

1. **User Action (UI):** Click in `standaloneWindow` (WebView) -> `iina.postMessage`.
2. **Controller (Plugin Script):** `onMessage` in `global.js`/`main.js` receives event.
3. **Logic:** Script calls `src/managers/*` or `src/api/*` to process data.
4. **Logging:** All modules use `Logger` from `src/utils/helpers.js`.
5. **Update (UI):** Script calls `win.postMessage` -> WebView `onMessage` updates DOM.

## Key Components

- **Standalone Window:** Main interface for browsing content with i18n support.
- **Player Interface:** OSD and controls during playback (`main.js`).
- **Storage:** `iina.preferences` for all data (100% portable, no file dependencies).
- **Logger:** Centralized logging utility with DEBUG flag auto-initialization.
- **Build System:** Parcel bundler for CommonJS output compatible with IINA runtime.

## Communication Patterns

### Plugin → WebView
```javascript
win.postMessage('render', items);
win.postMessage('error', message);
win.postMessage('backendReady', { version, timestamp });
```

### WebView → Plugin
```javascript
iina.postMessage('load', { type, category });
iina.postMessage('play', { id, type, ext });
iina.postMessage('ready');
```

### Event-Driven (main.js ↔ global.js)
```javascript
// global.js emits
iina.event.emit('iptv.play', { url, name, streamId, timestamp });

// main.js receives
iina.event.on('iptv.play', handlePlayRequest);
```

## Design Principles

1. **DRY**: Logger centralized, no duplicated code
2. **Modularity**: Clear separation of concerns (api, managers, core, utils)
3. **IINA Best Practices**: Use `iina.http` instead of external commands
4. **Portability**: All data stored in `iina.preferences` (no file system dependencies)
5. **Performance**: Virtual scrolling, request deduplication, lazy loading
